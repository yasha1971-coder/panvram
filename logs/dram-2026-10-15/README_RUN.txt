DRAM_LAT — Linux x86-64, без root, gcc -O2.

После распаковки ZIP одна команда из каталога DRAM_LAT:
    bash run.sh

Выбор логического CPU (необязательно):
    CPU=0 bash run.sh
По умолчанию выбирается первый CPU, разрешённый текущим cpuset/affinity.
Не выбирайте CPU вне разрешённого набора. Желательно оставить его SMT-соседа свободным.

Нужны gcc, bash, awk, coreutils, lscpu (обычный Ubuntu 22.04).
Нужно минимум 5 GiB MemAvailable; желательно >=6 GiB свободной RAM.
При контейнерных/cgroup лимитах дополнительно убедитесь, что вашему процессу разрешено >=5 GiB.
Скрипт не меняет governors, turbo, NUMA policy, swap или системные права.

Ожидаемое время: ориентировочно 2–10 минут, не измеренный результат EPYC 4344P.
Для большой точки каждый прогрев/замер проходит минимум весь цикл; время зависит от задержки RAM/TLB.
Пиковый рабочий массив 4 GiB; дополнительного массива перестановки нет.

Сначала gate: load1 <0.5 (до и после CPU sample); два /proc CPU-tick sample с интервалом >=1 s.
Чужой процесс с CPU >=10% одного логического CPU => STOP, STATUS=FAIL.
Собственный runner и его потомки исключены. Процесс, родившийся между samples, учитывается
консервативно по всем его CPU ticks. Завершившийся до второго sample процесс не виден:
gate — endpoint preflight, не непрерывный мониторинг и не защита от последующей нагрузки.
Недоступный или исчезнувший при чтении /proc process вызывает консервативный отказ.
Сборка и запуск идут после gate. Gate нельзя обойти флагом скрипта.

Метод: 18 размеров, степени двойки от 32 KiB до 4 GiB включительно.
Один указатель на 64-byte cache line. Sattolo с rejection sampling строит случайный
ЕДИНЫЙ цикл, который посещает каждый узел; фиксированный SplitMix64 seed 20261012.
Узлы создаются/first-touch после sched_setaffinity. Huge pages отключены для массива
через MADV_NOHUGEPAGE: результат включает задержки TLB/page walk, cache и DRAM,
а не изолированную физическую задержку DRAM. NUMA placement — обычный first-touch.
Работает один зависимый поток загрузок, без prefetch и параллельных независимых цепочек.
В каждом размере 3 прогрева + 9 замеров; минимум 4,194,304 обращений на trial либо
число узлов, если оно больше. Время CLOCK_MONOTONIC_RAW; медиана 9 значений.
Обращение = одна зависимая загрузка следующего указателя, не один байт и не вся cache line.
Аллокация, перестановка, прогревы и запись TSV не входят в timed interval.
Major page fault во время timed interval => FAIL, итоговый results.tsv не создаётся.
Значения включают накладные расходы chase-loop; для малых размеров это cache/loop latency.

Результаты: новый DRAM_LAT_results_<UTC>_<PID>/results.tsv, 9 raw trials и медиана
в нс/обращение; также lscpu.txt, uname.txt, gcc.txt, gate.txt, CPU samples, run.log,
source/binary SHA256 и STATUS. При отказе сохраняются диагностика и partial TSV,
но results.tsv не выдаётся за завершённый результат.
Повторный запуск создаёт новый каталог. OUT_DIR=/new/path задаёт иной новый каталог.

Проверка алгоритма отдельно (не полный benchmark):
    gcc -O2 -std=c11 -Wall -Wextra -Werror dram_lat.c -o dram_lat
    ./dram_lat --self-test
Для разработческой smoke-проверки без gate можно вызвать бинарник --max-bytes 1048576
--min-accesses 65536; такие результаты не являются принятым серверным прогоном.
